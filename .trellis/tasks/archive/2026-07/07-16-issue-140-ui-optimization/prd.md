# 优化 Issue #140 相关 UI

## Goal

在不改变 Issue #140 已落地的“文档主列表 + 新增表格弹窗”业务语义前提下，优化助手记忆页中记忆表相关界面的视觉层级、信息密度和操作体验。

## Confirmed Facts

- Issue #140 已关闭，核心实现提交为 `d0609c28`。
- 当前主列表以 `MemoryTableDocument` 为对象；模板选择与模板创建聚合在“新增表格”弹窗中。
- 已有文档整卡可进入编辑页，删除仅删除文档；助手记忆页创建的文档仍为助手作用域。
- 本任务是现有 UI 的后续优化，不重新设计 #140 的数据模型和作用域语义。
- 当前“新增表格”使用单个 `AlertDialog`，模板列表为不可滚动的普通 `Column`，模板增多或键盘弹出时存在布局溢出风险。
- 当前模板项只显示名称，不展示描述、作用域或“已添加”；但页面已派生 `primaryDocumentsByTemplate`，可用于 UI 状态呈现。
- 当前创建私有/全局模板分别占用 dialog 的 confirm/dismiss 操作槽位，作用域选择与创建动作混在一起。
- 当前文档卡只展示模板名及“作用域 · revision”，删除按钮常驻；空状态没有明确的新增 CTA。
- 仓库已有可复用的 `ModalBottomSheet` 选择列表、整卡信息卡、状态标签、overflow 危险操作和带 CTA 空状态模式。

## Requirements

- 保留现有文档优先的数据流、模板选择逻辑和持久化顺序。
- 优化主列表、空状态与“新增表格”流程的视觉和交互表现。
- 复用项目现有 Material 主题、深色模式与组件风格。
- 最终 UI 优化范围需结合当前界面实现和用户期望进一步收敛。
- 新增入口必须能容纳较多模板，并在小屏、横屏和输入法弹出时保持可操作。
- 已使用模板应显示明确的“已添加”状态；点击时打开已有文档，不伪装成新增。
- 模板选择项应至少展示名称、描述与模板作用域。
- 创建新模板时用显式作用域选择控件表达“私有/全局”，底部只保留单一创建动作。
- 文档卡应保留整卡进入编辑，弱化危险删除操作，并提升模板描述与状态信息的可扫读性。
- 新增模板选择器不得为规范化后同名的模板重复生成多行；去重只作用于 picker 投影，不能让历史模板文档从主列表消失。
- 提供明确的“管理模板”入口，管理列表保留每个历史模板 ID，并支持编辑名称/描述与删除。
- 创建或重命名模板时应阻止违反最终同名策略的名称，避免继续制造不可区分的模板。
- 删除模板必须明确提示会级联删除该模板 ID 下的所有文档；不得按名称批量删除其他模板。

## Acceptance Criteria

- [ ] 已有文档列表的信息层级更清晰，主要操作易于发现且点击区域合理。
- [ ] 空状态能够清晰引导用户新增记忆表。
- [ ] “新增表格”弹窗中模板选择、已添加状态和创建新模板入口易于区分。
- [ ] 不破坏 #140 已有的模板/文档作用域、导航和删除语义。
- [ ] UI 在浅色与深色主题下保持一致、无明显布局溢出。
- [ ] 模板列表可滚动；较多模板或键盘弹出时仍可选择模板、创建模板和取消。
- [ ] 已添加模板有清晰状态，点击后打开对应已有文档且不会重复创建。
- [ ] 新模板作用域通过明确控件选择，默认私有；全局选项带范围说明。
- [ ] 文档删除入口不与主点击目标竞争，二次确认显示可识别的表格名称而非原始 JSON。
- [ ] 新增/删除等图标操作具有本地化无障碍描述。
- [ ] picker 中规范化同名模板只出现一项，且优先项规则固定、可测试。
- [ ] 管理模板列表展示全部历史模板 ID，即使名称相同也能分别重命名或删除。
- [ ] 新建与编辑模板具有同名校验和明确错误提示。
- [ ] 删除模板只影响选中的模板 ID，并清楚告知文档级联影响。

## Out of Scope

- 修改 `MemoryTableTemplate` / `MemoryTableDocument` 数据模型或数据库结构。
- 改变一模板一助手文档、模板作用域或文档作用域规则。
- 在持久层增加文档唯一索引或自动合并历史重复文档。
- 模板 schema/列编辑继续由文档编辑器负责；本任务的管理页聚焦名称、描述、作用域展示和删除。
- 重组助手记忆页顶部全部能力设置；本轮聚焦 #140 的列表与新增流程。
- 模板搜索、筛选和排序；本轮用可滚动列表解决容量与小屏适配。

## Product Decision

- 用户确认采用分层 `ModalBottomSheet`：第一层选择模板，第二层创建新模板。
- 已添加模板点击后打开派生出的主文档；历史额外文档继续保留在主列表，不在本任务中合并或删除。

## New Feedback

- 主力机实测发现 picker 会同时显示多个不同 ID 的同名全局/助手模板。
- 当前新增流程缺少历史模板编辑、删除和冲突处理入口。

## Open Questions

- 无。用户明确认为当前可见范围内同名模板不应共存，创建时必须检测。

## Duplicate-name Decision

- 名称比较使用 trim、Unicode NFC、连续空白折叠和不区分大小写的规范化结果。
- 当前助手私有模板创建/重命名时，禁止与全局模板或当前助手其他私有模板同名。
- 全局模板创建/重命名时，禁止与数据库中任意模板同名，避免在任何助手的 effective 集合中制造冲突。
- 不新增数据库唯一索引：历史数据可能已有冲突，直接迁移会失败；冲突检查由 Repository 统一执行。
- 历史同名模板不自动删除或合并：picker 按名称折叠，管理页保留全部 ID 供重命名/删除。
- picker 冲突项优先级：已有主文档 > 当前助手私有 > 全局 > 更新时间较新 > ID 稳定排序。
- 管理页允许编辑/删除当前助手可见的私有和全局模板；全局删除必须额外提示会影响所有助手并级联删除该模板的全部文档。
