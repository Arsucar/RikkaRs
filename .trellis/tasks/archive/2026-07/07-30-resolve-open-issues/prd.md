## Requirements

- 主任务保存共同约束、子任务映射、跨子任务依赖与最终集成验收。
- 每个 Issue 对应一个可独立规划、实现、验证和归档的 Trellis 子任务。
- 先核对 Issue 正文、现有代码、已有 Trellis 任务和历史决策；已实现但尚未关闭的 Issue 不重复开发，只补齐验证与交付闭环。
- Issue 之间存在依赖时，在对应子任务规划中明确执行顺序，但每个子任务仍保留可测试的验收标准。
- GitHub Issue 关闭必须遵守仓库规范：分别发布事实一致的中文和英文交付评论，并写明目标分支、修复提交、正式版本（若有）、实际验证结果、定位与已知边界。
