# 修复 Issue 122 记忆模板助手隔离

## Goal

补齐 Issue #122 的助手隔离：不仅隔离记忆表文档，也要隔离助手作用域的记忆表模板定义。助手 A 创建、编辑或删除的助手模板不得在助手 B 中可见或可操作。

## Confirmed Facts

- 已关闭的 #122 修复主要覆盖文档的 `GLOBAL / ASSISTANT / CONVERSATION` 可见性，没有覆盖模板定义本身。
- 用户明确指出当前模板仍跨助手共享，因此原 Issue #122 未达到产品预期，Issue 已重新打开。
- `GLOBAL` 模板仍应保持共享；需要隔离的是归属于某个助手的模板。
- 修复必须覆盖持久化查询、编辑/删除入口、页面展示和生成/注入使用路径，不能只做 UI 隐藏。
- 用户已批准兼容迁移方案：旧模板迁移为 `GLOBAL`，升级后新模板默认归属当前助手；全局模板可复制为当前助手私有模板。

## Requirements

1. 助手 A 的助手作用域模板只对助手 A 可见；助手 B 同理。
2. 全局模板继续对所有助手可见，且不得因本修复变成助手私有。
3. 模板的新建、复制、更新、删除必须携带并校验所属 scope，不能通过已知 ID 跨助手覆盖或删除。
4. 助手页面、文档编辑器和聊天注入只使用当前助手可见的模板集合。
5. 兼容已有模板和备份/导入导出格式；若需要数据库迁移，必须定义确定性归属与回滚行为，不能静默丢失模板。
6. 保留上一轮 #122 已实现的文档隔离，不得回归。
7. 旧模板统一迁移为 `GLOBAL/__global__`；不得依据关联文档猜测助手归属。
8. 当前助手可把全局模板复制为新的助手私有模板；复制使用新 ID，不改变或删除原全局模板，也不自动复制其他助手数据。
9. AI 工具按当前助手执行模板及文档的已知 ID 读取、更新、删除，不能用 ID 绕过 scope 授权。

## Acceptance Criteria

- [ ] 助手 A 创建的助手模板在助手 B 的模板列表、选择器和编辑入口中均不可见。
- [ ] 助手 B 无法通过模板 ID 读取、更新或删除助手 A 的模板。
- [ ] 全局模板在 A/B 中均可见，行为与当前版本兼容。
- [ ] A/B 可以拥有名称相同但 ID/归属独立的助手模板，互不覆盖。
- [ ] 模板关联的文档仍遵守文档 scope 隔离；切换助手不会显示或注入另一助手的模板/文档。
- [ ] 旧数据升级后模板不丢失，归属规则有自动化测试。
- [ ] 全局模板复制后产生当前助手私有的新模板，原全局模板及其文档保持不变。
- [ ] AI 工具持有其他助手模板或文档 ID 时仍无法读取、覆盖或删除该数据。
- [ ] DAO/Repository 的真实查询与防御过滤、UI 派生逻辑、编辑授权均有回归测试。
- [ ] focused tests、Debug Kotlin 编译和 AndroidTest Kotlin 编译通过；有设备时安装并按双助手场景验收。

## Out of Scope

- 为每个助手拆分独立数据库。
- 改变 GLOBAL 模板的共享语义。
- 与模板隔离无关的记忆预算、排序或 UI 重设计。
