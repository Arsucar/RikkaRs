# 处理 GitHub Issues #142 与 #143

## Goal

在不破坏现有记忆数据和备份格式的前提下，同时交付结构化记忆 revision 可追溯/可回滚能力，以及离开备份页面后仍能完成的备份任务。

## Requirements

- #142 子任务负责本地结构化记忆 revision 历史、快照查看、差异展示和安全回滚；#143 子任务负责 WebDAV、S3、本地导出/导入任务的生命周期解耦。
- 两个子任务的状态、错误和取消语义必须可测试；不得把 `CancellationException` 当业务失败展示。
- 保留现有数据库、备份文件和导航兼容性；新增迁移必须向前兼容，不能修改已发布迁移。
- 当前迭代聚焦本地能力和现有 UI，不扩展远端 revision API、WorkManager/前台服务、完整审计日志、软删除回收站、analytics 或外部 deep link。

## Acceptance Criteria

- [ ] #142 在生产 DI 中启用快照 DAO；更新、历史查询和回滚均可用，回滚生成新 revision 且旧快照仍保留。
- [ ] #142 至少有一个现有记忆页面可进入历史列表、查看快照/差异并确认回滚，且加载、空、错误状态可见。
- [ ] #142 删除模板时不遗留该模板文档的快照；无权限或无效 revision 不修改当前数据。
- [ ] #143 备份/导出任务不再绑定 Tab 或 Backup 页面 Composition；返回、切换 Tab 后任务仍完成或明确被用户取消。
- [ ] #143 WebDAV、S3、本地导出路径成功后才记录备份时间；取消不显示失败 Toast，普通异常仍显示业务错误。
- [ ] 两个子任务均有自动化回归测试，并通过项目要求的编译/单元测试质量门禁。

## Out of Scope

- 进程被系统杀死后的可靠续跑、前台通知、远端 revision 同步和跨设备冲突协议。
- 完整 append-only 审计事件、权限系统、软删除/回收站和长期归档策略。
