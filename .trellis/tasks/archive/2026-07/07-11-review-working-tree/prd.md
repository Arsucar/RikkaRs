# 检查工作区更改

## Goal

审查当前 Git 工作区中的全部未提交更改，处理发现的临时数据泄露风险，并将预防规则沉淀为项目经验后提交推送。

## Requirements

- 检查已跟踪文件的 staged 与 unstaged diff，并识别相关未跟踪源码或配置文件。
- 结合调用关系、现有测试和仓库约定判断改动是否正确。
-  findings 按严重程度排序，并提供可定位的文件与行号。
- 不修改产品业务逻辑；仅处理临时产物、忽略规则、项目规范和任务记录。
- 忽略仅用于本地协作的 Trellis/agent 元数据，除非其变化本身会影响仓库工作流。
- 删除仓库根目录的临时设备截图和 UIAutomator XML dump。
- 增加明确的忽略规则，避免同类临时产物被宽泛暂存。
- 将本次风险与预防约定写入合适的项目 Trellis 规范。
- 完成检查后归档 Trellis 任务，提交并推送到当前分支，便于多平台查看。

## Acceptance Criteria

- [x] 已覆盖当前工作区内所有有意义的产品代码、测试、构建和 CI 差异。
- [x] 每个 finding 都描述触发条件、实际影响，并包含文件/行号引用。
- [x] 若未发现问题，明确说明未发现问题，并列出剩余测试风险。
- [x] 给出简短的审查范围和验证说明。
- [x] 根目录 `_*.png`、`_*.xml` 临时产物已清理且不会再次出现在 Git 状态中。
- [x] 项目规范记录 UI 调试产物的数据泄露风险和清理/忽略要求。
- [x] 相关更改和 Trellis 归档已提交并推送到当前远程分支。

## Notes

- 本任务仍使用 PRD-only 流程，新增工作仅涉及清理、忽略规则和规范沉淀。
- 默认不运行 `connectedDebugAndroidTest`，不安装 APK。
