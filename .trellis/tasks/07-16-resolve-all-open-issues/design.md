# 处理所有开放 GitHub Issues：总体设计

## Boundary

父任务只负责开放 Issue 清单、子任务映射、执行顺序、跨任务验收和最终 Issue 关闭；源代码实现归两个子任务所有，父任务不直接启动实现。

## Integration Contract

- 两个子任务完成后统一运行 app 模块编译、相关 JVM 测试、静态检查和真机安装验收。
- 数据库迁移测试与普通运行时测试分别归对应子任务，父任务只核对证据完整性。
- `CHANGELOG.md` 在所有实现完成后统一更新未发布变更，避免重复条目。
- 每个 Issue 使用自己的提交、验证证据、定位和已知边界生成中英文评论；重新读取评论后再关闭。
- 若某个 Issue 因真实外部条件无法完成，只保留该 Issue 开放并记录阻塞，不影响另一个 Issue 独立交付。

## Rollback

- #137 可通过独立提交回滚，不涉及持久化迁移。
- #136 的 schema 迁移发布后不可用简单代码回滚恢复归档字段；提交前必须以旧 schema 39 数据进行迁移验证，并确认所有会话行及组织关系保留。
